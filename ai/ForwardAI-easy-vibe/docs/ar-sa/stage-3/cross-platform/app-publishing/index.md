# نشر التطبيق المكتمل وإرساله إلى المتاجر

تشغيل التطبيق على جهازك لا يجعله منتجًا يمكن للمستخدم تثبيته بأمان.

> اختر القناة → ثبّت هوية التطبيق → ابنِ Release → وقّع → اختبر → جهز المتجر → أرسل للمراجعة → انشر تدريجيًا → راقب وحدّث

## 1. افصل الحزمة والتوقيع والتوزيع والمراجعة

الحزمة ملف التثبيت، والتوقيع يثبت الناشر ويحمي سلسلة التحديث، والتوزيع يوصله، والمراجعة تتحقق من قواعد المنصة.

## 2. نظّم الملكية والهوية

تتحكم المؤسسة في الحسابات والبريد والنطاق والسحابة والشهادات والدفع مع مصادقة ثنائية. لا تغيّر package name في Android أو Bundle ID في Apple بعد النشر. ارفع رقم البناء مع كل إرسال.

## 3. جهز Release حقيقيًا

لا تستخدم localhost أو قاعدة اختبار أو أسرار خادم. أنشئ الأيقونة واللقطات الحقيقية والوصف والدعم والخصوصية وتعليمات المراجعة من البناء المرشح. يجب أن تتفق الصلاحيات وSDK وتصريح المتجر وسياسة الخصوصية.

## 4. طرق المنصات

يرفع Android عادة ملف `.aab` موقّعًا إلى Google Play ويبدأ بالاختبار الداخلي. يستخدم iOS ‏App Store Connect وXcode Archive وTestFlight والمراجعة.

يستخدم Windows ‏MSIX في Microsoft Store أو مثبتًا موقّعًا على الموقع. يحتاج macOS خارج المتجر إلى Developer ID والتوثيق. يتيح Linux ‏Flathub وSnap وAppImage و`.deb` و`.rpm`.

يُنشر Web/PWA عبر HTTPS مع DNS والشهادة ومتغيرات الإنتاج و404 والعمل دون اتصال وManifest وService Worker والمراقبة والنسخ الاحتياطي.

## 5. المراجعة والنشر التدريجي

من الأخطاء الشائعة تعطل Release وحساب مراجعة غير صالح وتصريح خصوصية خاطئ وزر غير مكتمل وصلاحيات زائدة ومواد بلا ترخيص.

> هذه رسالة المراجعة: 【ألصقها】. حدد القاعدة والسلوك الذي يجب تغييره دون تخمين.

ابدأ باختبار المطور ثم الداخلي ونسخة تجريبية صغيرة والمراجعة ونسبة محدودة ثم الجميع. التوقيع والخصوصية والمراقبة والتراجع أجزاء من المنتج.
