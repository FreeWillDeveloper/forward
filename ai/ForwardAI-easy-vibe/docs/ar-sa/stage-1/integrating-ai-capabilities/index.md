أصبح النموذج الأولي في الفصل السابق صالحًا لفحص بنية الصفحات ومسار الاستخدام، لكن نتائجه المولدة ما زالت بيانات تجريبية. سنربط في هذا الفصل أحد أفعاله الأساسية بخدمة ذكاء اصطناعي حقيقية.

لا يعني الربط نسخ بضعة أسطر من API فحسب. نحتاج إلى معالجة ثلاثة أمور معًا: **كيف نصف المهمة، وكيف نقرأ الوثائق الرسمية، وكيف نضع الاستدعاء بأمان داخل مسار المنتج.**

## 1. حدد الوظيفة التي ستربطها

تحتوي مساحة محتوى المتجر من الفصل السابق على معلومات المنتج وزر «توليد النص»، لكن النتيجة ما زالت وهمية. سنجعل هذا الزر يعمل فعلًا أولًا.

المسار بسيط: يملأ المستخدم اسم المنتج ومادته ومزاياه، ثم يضغط الزر فيستلم نصًا للمنتج. المدخل والنتيجة كلاهما نص، لذا نحتاج إلى نموذج لتوليد النصوص.

إذا اختلفت الوظيفة، اختلفت القدرة المطلوبة:

- رفع صورة منتج والتعرف على لونه وشكله يحتاج إلى فهم الصور.
- صنع ملصق من معلومات المنتج يحتاج إلى توليد الصور.
- تحويل تسجيل إلى محضر يحتاج أولًا إلى تحويل الصوت إلى نص، ثم تنظيمه بنموذج نصي.
- تحويل مقال إلى صوت مسموع يحتاج إلى تحويل النص إلى كلام.
- تحريك صورة المنتج يحتاج إلى توليد فيديو من صورة.

راجع الصفحة قبل الربط: ماذا سيرسل المستخدم، وماذا يريد أن يرى في النهاية؟ عندما يتضح الأمران يسهل اختيار النص أو الصورة أو الصوت أو الفيديو.

### 1.1 قد تنقسم الوظيفة الواحدة إلى خطوات

لا يستطيع نموذج واحد إنهاء كل وظيفة في طلب واحد. «رفع صورة وكتابة المزايا» يعني فهم المنتج في الصورة أولًا ثم كتابة النص من النتيجة. و«الإجابة من ملفات الشركة» تعني العثور على المادة المناسبة قبل صياغة الجواب.

لا تبدأ بأسماء النماذج. اتبع عمل المستخدم: ما الخطوة التي تفهم محتوى موجودًا، وما التي تنشئ محتوى جديدًا، وما التي تبحث فقط عن معلومات؟ اربط قدرتين أو ثلاثًا بالتتابع عند الحاجة.

يتولى الذكاء الاصطناعي الجزء المناسب له فقط. تسجيل الدخول والدفع وحفظ الملفات والتنقل لها قواعد واضحة، وتظل من عمل البرنامج العادي.

![صفحة فعلية تفهم صورة المنتج قبل توليد وصفه](../../../zh-cn/stage-1/integrating-ai-capabilities/images/index-2026-01-20-15-35-41.webp)

*في هذا النموذج تُقرأ معلومات المنتج أولًا، ثم يؤكدها المستخدم قبل توليد وصف ومزايا قابلة للتحرير.*

### 1.2 ما الذي تبحث عنه في لوحة الخدمة؟

بعد اختيار توليد النص، افتح منصة مثل DeepSeek أو SiliconFlow أو Volcengine Ark أو MiniMax. توفر المنصة الحساب والفوترة ونقطة الوصول، بينما يعالج النموذج المختار الطلب.

في أول ربط يكفي العثور على أربعة أشياء:

1. إنشاء **API Key** تستعمله الصفحة لاستدعاء الخدمة.
2. تسجيل **Model ID** للنموذج المراد.
3. العثور على أصغر مثال curl أو JavaScript في الوثائق الرسمية.
4. فحص الحصة والسعر وحدود الاستدعاء.

يرسل التطبيق معلومات المنتج عبر **API**. يمكن استعمال **SDK** لـ JavaScript أو Python إن توفر؛ فهو يغلف كود الطلب ليسهل استعماله. والجملة «اكتب عنوانًا ومزايا من هذه المعلومات» داخل الطلب هي التعليمات المرسلة للنموذج.

اسم المنصة ومعرّف النموذج وعنوان API ليست الشيء نفسه. استعمل العنوان والمعرّف في المثال الرسمي، لا عنوان صفحة التجربة.

### 1.3 اترك الواجهات غير اللازمة لوقت لاحق

قد تظهر Embedding وRerank وFunction Calling وOCR ومراجعة المحتوى. تُستخدم Embedding وRerank في قواعد المعرفة، وOCR لقراءة PDF والفواتير، وFunction Calling لاستخدام البحث أو قواعد البيانات.

لا يلزم تعلمها الآن. اربط API واحدة تخدم وظيفة واضحة في الصفحة، ثم عد إلى الوثائق عندما يحتاج المنتج إلى قدرة جديدة.

## 2. جرّب النتيجة قبل كتابة الكود

اختبر النموذج في مساحة التجربة على المنصة قبل كتابة API. لا نريد فقط معرفة قدرته على الكتابة، بل قدرته على إعادة التنسيق الذي تحتاج إليه الصفحة.

### 2.1 يكفي أن يشرح المستخدم ما يريد

اكتب كما يكتب مستخدم حقيقي:

```text
أريد عرض حقيبة ظهر خفيفة للتنقل اليومي، مصنوعة من النايلون الأسود.
اكتب عنوانًا قصيرًا للمنتج وثلاث مزايا.
```

بعد بناء الصفحة لن يحتاج المستخدم إلى صياغة هذه الفقرة. يملأ الاسم والمادة واللون ثم يضغط الزر، فيضيف البرنامج قواعد ثابتة: لا تختلق سعرًا أو مبيعات، اجعل العنوان قصيرًا، وأعد تنسيقًا محددًا.

إذا كانت الصفحة تعرض العنوان والملخص والمزايا منفصلة، يمكن للبرنامج طلب حقول JSON:‏ `title` و`summary` و`selling_points`. تبقى الكتابة طبيعية وتقرأ الصفحة النتيجة بثبات.

جرّب عدة منتجات واحذف حقلًا عمدًا لتعرف هل يخترع النموذج معلومة ناقصة. إذا اضطرب التنسيق، حسّن التعليمات الثابتة في البرنامج بدل مطالبة كل مستخدم بتعلم كتابة التعليمات.

### 2.2 اربط API بالصفحة

توفر الوثائق عادة مثال curl أو JavaScript أو Python. أعط المثال إلى بيئة التطوير المدعومة بالذكاء الاصطناعي مع وصف الوظيفة.

```text
أضف زر «توليد النص» إلى صفحة تفاصيل المنتج.

عند الضغط، أرسل معلومات المنتج الحالية إلى API أدناه،
ثم اعرض النص الناتج في الصفحة.

لا تضع API Key في المتصفح. اعرض حالة الانتظار ورسالة الفشل.
بعد الانتهاء أخبرني بما يجب إعداده وكيف أشغّل الصفحة وأختبرها.

مثال API الرسمي:
<ألصق مثال curl أو SDK من دون مفتاح حقيقي>
```

مع مكان الزر والمثال الرسمي لا تحتاج البيئة إلى تخمين تنسيق API. تأكد أولًا من نجاح طلب واحد. عند إضافة صورة أو صوت أو فيديو، استبدل وصف الوظيفة والمثال الرسمي.

## 3. أرسل أول طلب من المثال الرسمي

بعد اختبار التعليمات افتح Quick Start أو API Reference. يحتاج أول استدعاء إلى أربعة أمور: عنوان الطلب، موضع API Key، قيمة `model`، وأصغر مثال رسمي.

انسخ مثال curl أو JavaScript أو Python وغيّر معرّف النموذج ومحتوى الاختبار فقط. احصل على استجابة طبيعية في الطرفية قبل إدخال الكود في المشروع. إن فشل ربط الصفحة لاحقًا، ستعرف أن الحساب والمفتاح والنموذج تعمل.

افحص الاستجابة أيضًا. يوجد النص عادة في حقل JSON، وقد تعود الصورة بعنوان URL، والصوت ببيانات ثنائية، والفيديو بمعرّف مهمة أولًا. يجب أن تُبنى الصفحة وفق ما تعيده الواجهة فعلًا.

### 3.1 اطلب من الذكاء الاصطناعي قراءة الوثيقة الطويلة

لا يلزم قراءة الوثائق من أولها إلى آخرها. أعط رابط الصفحة إلى البيئة واطلب ما يلزم لأول استدعاء فقط.

```text
اقرأ وثائق API هذه: <الرابط>

أريد استدعاءها من JavaScript. أعطني أبسط مثال،
وموضع API Key وmodel، وكيف أقرأ النتيجة.
استخدم المعاملات المذكورة في هذه الصفحة فقط.
```

## 4. الزيارة الأولى للوحة الخدمة

يتم إنشاء المفتاح واختيار النموذج وفحص الاستهلاك عادة في اللوحة. قد تختلف أسماء القوائم، لكن الخطوات متشابهة.

### 4.1 أنشئ المفتاح وتأكد من وصول الطلب

API Key هي بيانات اعتماد التطبيق. ضعها في متغير بيئة محلي ولا تعرضها في لقطة أو محادثة أو كود المتصفح. إذا اشتبهت في تسربها فألغها فورًا وأنشئ غيرها.

بعد أول طلب افتح Usage أو Billing وابحث عن سجل جديد. سترى أيضًا الرصيد وQuota. عند الفشل ميّز بين كود لم يرسل، ومنصة رفضت الطلب، وحساب نفدت حصته.

![صفحة Usage في DeepSeek تعرض الرصيد والإنفاق الشهري واتجاه الاستدعاءات](../../../zh-cn/stage-1/integrating-ai-capabilities/images/index-2026-01-20-13-57-41.png)

*تعرض صفحة Usage حجم الاستدعاءات والتكلفة والرصيد.*

احتفظ بـ Request ID أو Trace ID إن ظهر في الخطأ؛ يساعدك في العثور على الطلب المحدد بين استدعاءات كثيرة.

### 4.2 اختر النموذج وانسخ اسم الاستدعاء الدقيق

يعرض كتالوج النماذج ما هو متاح للنص والصورة والصوت والفيديو. افتح التفاصيل وانسخ Model ID المستخدم في الكود؛ فقد يختلف عن الاسم الظاهر.

![كتالوج SiliconFlow مع مرشحات للنص والصورة والفيديو والصوت](../../../zh-cn/stage-1/integrating-ai-capabilities/images/index-2026-01-20-15-05-04.webp)

*يمكن تصفية كتالوج SiliconFlow بحسب نوع القدرة.*

تطلب بعض المنصات اختيار Region أو إنشاء Deployment قبل إظهار Base URL وEndpoint. اتبع دليل البدء السريع ولا تستعمل عنوان لوحة التحكم بوصفه عنوان API.

![صفحة الوصول السريع في Volcengine Ark تعرض المفتاح وخطوات التجربة](../../../zh-cn/stage-1/integrating-ai-capabilities/images/index-2026-01-20-23-13-01.png)

*تجمع Volcengine Ark إنشاء المفتاح واختيار النموذج والمثال القابل للتشغيل.*

### 4.3 حدود الاستخدام والمهام الطويلة

تعني RPM وTPM عدد الطلبات والرموز المسموح بها في الدقيقة. وقد تحد خدمات الصورة والصوت والفيديو Concurrency، أي عدد المهام المتزامنة. عند تجاوز الحد يظهر غالبًا `429`؛ انتظر بدل الضغط المتكرر.

لا يعيد الفيديو الملف فورًا، بل Task ID. يستعلم البرنامج عن التقدم أو تستخدم الخدمة Callback/Webhook لإبلاغ الخادم. قد تنتهي صلاحية File ID أو URL المؤقت، لذلك قرر قبل النشر هل ستنسخ الملف إلى تخزينك.

اترك `max_tokens` و`temperature` و`stream` كما في المثال الرسمي في النسخة الأولى. غيّر `max_tokens` عند انقطاع الخرج و`stream` عند الحاجة إلى العرض التدريجي، ولا تعدّل كل شيء معًا.

## 5. انقل المثال الرسمي إلى الصفحة

بعد نجاح المثال في الطرفية اتبع هذا الترتيب:

1. ضع المفتاح في `.env.local` أو ملف لا يُرفع إلى Git.
2. استدعِ النموذج من الخادم أو Serverless Function.
3. اجعل الصفحة تستدعي مسارك `/api/...` من دون حمل مفتاح الطرف الثالث.
4. أضف حالات الانتظار والنجاح والفشل إلى الزر.
5. عد إلى Usage وتأكد من ظهور الاستدعاء الحقيقي.

```text
صفحة المتصفح
    │ ترسل بيانات العمل فقط
    ▼
مسار /api الخاص بك ── يقرأ API Key من بيئة الخادم
    │
    ▼
خدمة الذكاء الاصطناعي ── تعيد نصًا أو JSON أو ملفًا أو task_id
```

::: warning حماية API Key
لا تكتب المفتاح في كود Vue أو React أو HTML الأمامي. حتى المتغير الذي يبدأ بـ `VITE_` أو `NEXT_PUBLIC_` قد يصل إلى ملفات المتصفح العامة. عند النشر، يستدعي النموذج خادم خلفي أو Serverless Function أو بوابة محمية.
:::

### 5.1 بعض الواجهات لا تعيد النتيجة فورًا

يعيد النص القصير وفهم الصورة ونسخ الصوت القصير النتيجة غالبًا في طلب واحد. أما الحوار أو الصوت المباشر فقد يصل على دفعات وتعرضه الصفحة أثناء الاستقبال.

يعمل توليد الصور والفيديو غالبًا بصورة غير متزامنة: يعيد الطلب الأول `task_id` فقط، ثم تستعلم الصفحة عن الانتظار والمعالجة والنجاح والفشل. قد يستغرق ذلك عشرات الثواني، فلا تترك رسالة تحميل ثابتة.

## 6. ابدأ بتوليد النص

توفر [وثائق DeepSeek API](https://api-docs.deepseek.com/) واجهة نصية متوافقة مع SDK شائعة. تتغير النماذج؛ انسخ المعرّف الحالي من [قائمة النماذج](https://api-docs.deepseek.com/api/list-models).

أرسل أولًا طلب curl ببيانات المنتج نفسها المستخدمة في التجربة.

```bash
curl https://api.deepseek.com/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${DEEPSEEK_API_KEY}" \
  -d '{
    "model": "deepseek-v4-flash",
    "messages": [
      {"role": "system", "content": "أعد JSON يحوي title وsummary وselling_points. يجب أن تتضمن selling_points ثلاثة عناصر. لا تخترع سعرًا أو مبيعات أو فوائد."},
      {"role": "user", "content": "أريد عرض حقيبة ظهر سوداء من النايلون للتنقل اليومي. اكتب عنوانًا قصيرًا وفقرة تعريفية وثلاث مزايا."}
    ],
    "stream": false
  }'
```

ضع المفتاح في متغير بيئة ثم شغّل الأمر. بعد استجابة صحيحة أعط المثال نفسه وتعليمات القسم 2 إلى بيئة التطوير. اجعل النسخة الأولى زرًا واحدًا وبيانات منتج ثابتة، ثم اربط النموذج الكامل.

### جرّب بيانات منتجين

غيّر الاسم والمادة واللون. إذا طابقت النتيجتان مدخلاتهما وعُرضتا جيدًا فقد نجح الربط الأدنى. احذف بعد ذلك حقلًا وافحص اختلاق الأسعار أو الفوائد أو المبيعات. استخدم مفتاحًا خاطئًا مؤقتًا لاختبار رسالة الفشل.

تأكد أخيرًا من الاستدعاءات في Usage. ظهور نص في الصفحة لا يثبت وصول API، فقد تعطي البيانات الوهمية القديمة النتيجة نفسها.

## 7. فهم الصور باستخدام Qwen3-VL

يستقبل نموذج الرؤية صورة وسؤالًا. اسأل عن المعلومات التي تحتاجها الصفحة؛ سؤال عام مثل «ماذا في الصورة؟» يعيد عادة وصفًا واسعًا.

```text
افحص صورة المنتج. اذكر نوعه ولونه الأساسي والمواد والبنية الظاهرة،
وانسخ النص الموجود في الصورة.

قل بوضوح ما لا يظهر، ولا تخمن العلامة أو السعر أو المبيعات.
أعد JSON حتى أعرض النتيجة في الصفحة.
```

يمكن تصفية نماذج الرؤية الحالية في [كتالوج SiliconFlow](https://cloud.siliconflow.cn/models). نستخدم `Qwen/Qwen3-VL-8B-Instruct` لشرح البنية؛ تحقق من Model ID الحالي قبل التشغيل.

```python
import base64
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["SILICONFLOW_API_KEY"],
    base_url="https://api.siliconflow.cn/v1"
)

with open("product.jpg", "rb") as image_file:
    image_data = base64.b64encode(image_file.read()).decode("utf-8")

response = client.chat.completions.create(
    model="Qwen/Qwen3-VL-8B-Instruct",
    messages=[{
        "role": "user",
        "content": [
            {"type": "text", "text": "أعد JSON لنوع المنتج ولونه ومواده وبنيته الظاهرة والنص في الصورة. لا تخمن ما لا يظهر."},
            {"type": "image_url", "image_url": {
                "url": f"data:image/jpeg;base64,{image_data}"
            }}
        ]
    }]
)
```

*يسهل اكتشاف الخطأ عندما يؤكد المستخدم معلومات المنتج المقروءة قبل توليد النص النهائي.*

## 8. توليد صور المنتج وتعديلها

يستطيع [Seedream](https://seed.bytedance.com/en/blog/deeper-thinking-more-accurate-generation-introducing-seedream-5-0-lite) توليد صورة من النص أو تعديل صورة مرجعية. في صور المنتجات يجب توضيح ما لا يجوز تغييره، إلى جانب الخلفية والتكوين والإضاءة.

```text
حوّل حقيبة الظهر السوداء في الصورة المرجعية إلى ملصق منتج عمودي.
ضعها وسط سطح رمادي فاتح بإضاءة ناعمة واترك مساحة للعنوان في الأعلى.
لا تضف نصًا أو شعارًا أو سعرًا، ولا تغيّر السحّابات أو الحمالات أو الجيوب.
```

افحص تشوه المنتج قبل الخلفية والتكوين، ولا تبدأ بقائمة طويلة من كلمات الأسلوب.

انسخ Model ID الحالي وأصغر طلب من [لوحة Volcengine Ark](https://www.volcengine.com/experience/ark?launch=seedream)، ولا تعتمد طويلًا على رقم إصدار في درس قديم.

```bash
curl -X POST https://ark.cn-beijing.volces.com/api/v3/images/generations \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${ARK_API_KEY}" \
  -d '{
    "model": "<انسخ Model ID الحالي من اللوحة>",
    "prompt": "حوّل حقيبة الظهر السوداء المرجعية إلى ملصق عمودي بسيط. لا تضف نصًا أو شعارًا أو سعرًا ولا تغيّر بنية الحقيبة.",
    "image": ["https://example.com/product-reference.png"],
    "response_format": "url",
    "stream": false,
    "watermark": false
  }'
```

![نتيجة توليد الصور بعد دمجها في المنتج](../../../zh-cn/stage-1/integrating-ai-capabilities/images/index-2026-01-20-23-21-13.webp)

قد تنتهي صلاحية عناوين الصور. يمكن للنموذج عرضها مباشرة، أما المنتج المنشور فيقرر وفق شروط الخدمة نقلها إلى تخزينه ويسجل التعليمات وإصدار النموذج والوقت.

## 9. التعرف على الصوت وتوليده واجهتان مختلفتان

- **ASR / STT** يحول الكلام أو ملف الصوت إلى نص.
- **TTS** يحول النص إلى كلام قابل للتشغيل.

مدخلاتهما ومخرجاتهما وتجربة الصفحة مختلفة، فلا تجمعهما خلف زر مبهم اسمه «API الصوت».

### 9.1 من الصوت إلى النص: ارفع الملف واستلم التفريغ

ترفع [وثائق النسخ الصوتي في SiliconFlow](https://docs.siliconflow.cn/cn/api-reference/audio/create-audio-transcriptions) الملف بصيغة `multipart/form-data` بدل JSON.

```bash
curl --request POST \
  --url https://api.siliconflow.cn/v1/audio/transcriptions \
  -H "Authorization: Bearer ${SILICONFLOW_API_KEY}" \
  -F "file=@meeting.mp3" \
  -F "model=FunAudioLLM/SenseVoiceSmall"
```

```text
أضف زر «رفع التسجيل ونسخه» إلى الصفحة الحالية.

بعد رفع ملف mp3 أو m4a أو wav، استدعِ API أدناه من الخادم،
ثم ضع النص الناتج في حقل قابل للتحرير.
احفظ API Key في متغير بيئة واسمح بإعادة المحاولة بعد الخطأ.

المثال الرسمي:
<ألصق مثال curl أعلاه>
```

### 9.2 قد يعيد تحويل النص إلى كلام صوتًا لا JSON

توفر [وثائق MiniMax T2A HTTP](https://platform.minimax.io/docs/api-reference/speech-t2a-http) توليدًا متزامنًا للصوت. يستخدم المثال الحالي `speech-2.8-hd`؛ تحقق من النموذج والصوت على المنصة.

هيئ الأرقام والاختصارات والوقفات للقراءة، ثم اختر الصوت والسرعة والحجم والعاطفة والتنسيق. لا ترسل صفحة كاملة فيها Markdown وروابط ونصوص أزرار إلى القارئ.

```bash
curl --request POST \
  --url https://api.minimax.io/v1/t2a_v2 \
  --header "Authorization: Bearer ${MINIMAX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "speech-2.8-hd",
    "text": "هذه عينة صوتية من تعريف المنتج.",
    "stream": false,
    "output_format": "hex",
    "language_boost": "auto",
    "voice_setting": {
      "voice_id": "<انسخ voice_id من قائمة الأصوات>",
      "speed": 1,
      "vol": 1,
      "pitch": 0
    },
    "audio_setting": {
      "sample_rate": 32000,
      "bitrate": 128000,
      "format": "mp3",
      "channel": 1
    }
  }'
```

تحتاج صفحة الصوت أيضًا إلى تشغيل وإيقاف وإعادة توليد وتنزيل. يستخدم TTS المتدفق WebSocket أو HTTP المتدفق ويشغل الأجزاء عند وصولها.

::: warning الصوت والخصوصية
اشرح غرض التسجيل ومدة حفظه وطريقة حذفه قبل رفعه. يتطلب استنساخ الصوت إذنًا واضحًا من صاحبه. لا تستخدم تسجيلات الآخرين أو المشاهير مجهولة المصدر.
:::

## 10. توليد الفيديو: أنشئ مهمة وانتظر النتيجة

تعمل API الفيديو عادة بصورة غير متزامنة. يقسم [دليل MiniMax للفيديو](https://platform.minimax.io/docs/guides/video-generation) العمل إلى إنشاء مهمة واستلام `task_id`، ثم الاستعلام حتى `file_id`، ثم جلب رابط التنزيل.

### 10.1 صف أيضًا كيف يتغير المشهد

تحتاج تعليمات الفيديو إلى موضع البداية وترتيب الحركة واتجاه الكاميرا والمدة.

```text
اعرض حقيبة الظهر السوداء ست ثوانٍ على منصة رمادية فاتحة.
تتحرك الكاميرا ببطء من الأمام إلى اليمين، ثم تقترب قليلًا. حافظ على الإطار العمودي.
لا تغيّر الحقيبة ولا تضف أشخاصًا أو نصًا أو شعارًا.
```

إذا كثرت الحركات، ابدأ بلقطة واحدة وحركة رئيسية واحدة. الدوران والفتح والتقريب وتغيير المشهد معًا يصعّب ثبات شكل المنتج.

### 10.2 الإنشاء والاستعلام طلبان منفصلان

```bash
# الخطوة الأولى: إنشاء المهمة
curl --request POST \
  --url https://api.minimax.io/v1/video_generation \
  --header "Authorization: Bearer ${MINIMAX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "MiniMax-Hailuo-2.3",
    "prompt": "اعرض حقيبة ظهر سوداء على منصة رمادية فاتحة. تتحرك الكاميرا من الأمام إلى اليمين ثم تقترب. لا تغيّر الحقيبة ولا تضف أشخاصًا أو نصًا أو شعارًا.",
    "duration": 6,
    "resolution": "1080P"
  }'

# الخطوة الثانية: الاستعلام باستخدام task_id العائد
curl --request GET \
  --url "https://api.minimax.io/v1/query/video_generation?task_id=<TASK_ID>" \
  --header "Authorization: Bearer ${MINIMAX_API_KEY}"
```

تعرض الصفحة `Preparing` و`Queueing` و`Processing` و`Success` و`Fail`. حدد فاصل الاستعلام وشرط التوقف، ويمكن للمنتج المنشور استخدام `callback_url` لإبلاغ الخادم.

::: warning الفيديو ومواد الأشخاص الحقيقيين
عند استعمال صور أو أصوات أشخاص أو علامات أو مواد محمية، تحقق من الإذن وقواعد المنصة. قد تطلب الخدمة تحقق الوجه أو تسجيل الأصول أو مراجعة المحتوى، ولا يجوز تجاوز ذلك من المتصفح.
:::

## 11. تشخيص المشكلات الشائعة

| الظاهرة | ما يجب فحصه أولًا |
| --- | --- |
| `401 / 403` | صحة المفتاح وصلاحيته وموضعه في الترويسة |
| `404` | Base URL وEndpoint وModel ID الحالية |
| `429` | RPM وTPM والتزامن ومستوى الحساب |
| `400` | المعاملات المطلوبة وتنسيق الملف وبنية JSON والحجم |
| `5xx / timeout` | حالة الخدمة والمهلة وإعادة المحاولة |
| انتظار مستمر | التزامن واستعلام الحالة والحصة وازدحام الخدمة |
| نجاح بلا محتوى | مسار حقل الاستجابة والبيانات الثنائية وانتهاء URL |
| يعمل محليًا ويفشل منشورًا | متغيرات البيئة وCORS ومهلة Serverless وشبكة المنطقة |

احتفظ بوقت الخطأ ونوع الطلب وحالة HTTP وRequest ID أو Trace ID. لا تسجل API Key أو تسجيل المستخدم كاملًا أو بيانات العمل الحساسة.
